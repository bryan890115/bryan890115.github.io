Sentiment Analysis

Sentiment analysis predicts an evaluative stance expressed in text. Before choosing a model, the task must say whose sentiment matters, what its target is, which labels are allowed, and how ambiguity or mixed opinions are handled.

Define the unit and target

Document-level classification assigns one label to a whole review. Sentence-level classification narrows the unit but can still combine several targets. Aspect-based analysis separates targets: “the screen is bright but the battery is weak” contains positive and negative evaluations at once.

Labels may be binary, multi-class, ordinal, or continuous. Neutral is not the same as uncertain, irrelevant, or evenly mixed. These states should only be combined when the application can tolerate the lost distinction.

Annotation is part of the model specification

Annotators need rules for quotation, sarcasm, hypothetical statements, politeness, and target scope. Multiple independent judgements reveal where the scheme is unclear. Agreement does not prove objective truth, but low agreement warns that the labels or instructions may not support a reliable prediction task.

Worked example: why accuracy can mislead

Imagine 100 synthetic messages: 90 are neutral and 10 are negative. A classifier that always predicts neutral has \(90\%\) accuracy but negative-class recall \(0/10=0\). If missed negative messages are costly, the high accuracy is operationally useless.

For a chosen positive class, precision and recall are

\[ \operatorname{precision}=\frac{TP}{TP+FP},\qquad \operatorname{recall}=\frac{TP}{TP+FN}. \]

Macro-averaging gives each class equal weight; micro-averaging pools decisions and therefore gives frequent classes more influence.

Approach ladder

  1. Rules and lexicons: sum known word orientations, then handle negation or intensifiers with explicit logic.
  2. Statistical classifiers: learn weights for sparse token or character features.
  3. Neural models: learn representations and interactions from labelled examples.
  4. Pretrained Transformers: adapt contextual representations or prompt a model to emit constrained labels.

Increasing model complexity may help with context, but it does not repair a vague target or a shifted evaluation set.

Executable example: a scoped lexicon baseline

This example uses a tiny invented vocabulary and flips the next sentiment word after “not.” It is intentionally limited, deterministic, and useful as an error-analysis baseline.

LEXICON = {"clear": 2, "useful": 1, "slow": -1, "confusing": -2}

def sentiment(tokens):
    score = 0
    negate_next = False
    for token in tokens:
        if token == "not":
            negate_next = True
            continue
        value = LEXICON.get(token, 0)
        score += -value if negate_next and value else value
        if value:
            negate_next = False
    return score

examples = {
    "clear and useful": 3,
    "useful not confusing": 3,
    "clear but slow": 1,
}
for text, expected in examples.items():
    assert sentiment(text.split()) == expected
print([sentiment(text.split()) for text in examples])

The rule fails on long-range negation, irony, new vocabulary, and target-specific sentiment. Recording those error types is more informative than treating the baseline score as a final answer.

Evaluation and deployment

Split data so that near-duplicate authors, templates, or conversations do not leak across training and testing. Inspect results by class, target, time period, language variety, and message length. When scores drive consequential actions, calibrate confidence and define an abstention route.

Sentiment is especially sensitive to domain shift: “unpredictable” can praise a story but criticise a service. A deployed system therefore needs drift checks, sampled human review, and a way to revise the label scheme when real inputs expose missing categories.
