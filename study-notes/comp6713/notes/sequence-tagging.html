Sequence Tagging

Sequence tagging predicts a structured label sequence aligned with input tokens. Local evidence matters, but neighbouring labels constrain one another, so the best sequence need not contain the individually best label at every position.

Tasks and label schemes

Part-of-speech tagging labels grammatical roles such as noun or verb. Named-entity recognition marks spans such as organisations or locations. Other taggers can identify chunks, events, or domain-specific mentions.

BIO encoding represents spans with B for the first token, I for subsequent tokens, and O outside any span. Entity types can be attached, producing labels such as B-ORG and I-ORG. A valid sequence cannot begin an organisation span with I-ORG unless the chosen scheme explicitly defines a repair.

Worked example: aligned labels

For the invented sentence “Mira joined North Wind,” a possible organisation annotation is:

TagOOB-ORGI-ORG

Tokenisation and labelling must agree on boundaries. A subword model often predicts over pieces and then maps those predictions back to the task’s token or character spans.

HMMs, CRFs, and neural taggers

A hidden Markov model describes a joint probability using transition and emission terms:

\[ P(y_{1:T},x_{1:T})=P(y_1)P(x_1\mid y_1) \prod_{t=2}^{T}P(y_t\mid y_{t-1})P(x_t\mid y_t). \]

The Viterbi algorithm finds the highest-probability tag path without enumerating every sequence. A linear-chain conditional random field directly scores \(P(y_{1:T}\mid x_{1:T})\), allowing overlapping features of the observed sequence while still decoding globally. Neural taggers learn contextual token representations; a CRF output layer may be added when explicit transition structure remains useful.

Executable example: Viterbi decoding

This synthetic two-state decoder uses log-scores, so path multiplication becomes addition. Stable iteration order makes ties deterministic.

states = ("N", "V")
start = {"N": -0.2, "V": -1.2}
transition = {
    "N": {"N": -1.0, "V": -0.1},
    "V": {"N": -0.2, "V": -1.1},
}
emission = {
    "N": {"sparks": -0.1, "settle": -1.4},
    "V": {"sparks": -0.8, "settle": -0.1},
}

def viterbi(tokens):
    paths = {state: (start[state] + emission[state][tokens[0]], [state]) for state in states}
    for token in tokens[1:]:
        updated = {}
        for current in states:
            choices = [
                (score + transition[previous][current] + emission[current][token], path + [current])
                for previous, (score, path) in paths.items()
            ]
            updated[current] = max(choices, key=lambda item: (item[0], item[1]))
        paths = updated
    return max(paths.values(), key=lambda item: (item[0], item[1]))

score, tags = viterbi(["sparks", "settle"])
assert tags == ["N", "V"]
print(tags, round(score, 1))

Evaluation and error analysis

Token accuracy is informative for dense labels such as parts of speech, but it can be dominated by common tags. Entity extraction is usually evaluated at the span level: the predicted start, end, and type must match the reference. Partial overlaps should be analysed separately rather than silently counted as success.

Useful error categories include boundary errors, type confusions, unseen names, tokenisation mismatches, invalid BIO transitions, and context-dependent words. Compare against a simple majority or dictionary baseline and report performance on rare labels, not only the aggregate.
